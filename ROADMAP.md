# ROADMAP

## OpenAI Model Config Rollout

- Разделить "рефакторинг конфигурации моделей" и "удешевление по умолчанию" на разные этапы.
- Для безопасного rollout оставить исходные production-дефолты в `config.ts`, чтобы вынос моделей в конфиг не менял поведение без явного `env`.
- Перевод на более дешёвые модели (`gpt-5.4-mini`, `text-embedding-3-small` и т.д.) включать отдельным коммитом или только через заданные `OPENAI_MODEL_*` переменные.
- Перед сменой дефолтов проверить качество в трёх критичных зонах:
  - классификация интентов и dedup;
  - качество retrieval после смены embedding-модели;
  - сценарии анализа переписки и memory extraction.

## LLM Provider Abstraction

- Поддержать второй текстовый LLM-провайдер, не ломая текущий OpenAI-only путь.
- Вынести выбор не только модели, но и провайдера на уровень конфигурации задач:
  - `intentClassification`
  - `intentDedup`
  - `conversation`
  - `messageAnalysis`
  - `memoryExtraction`
  - `memoryConsolidation`
  - `webSearchReasoning`
  - `browserPlanning`
- Ввести абстракцию поверх провайдеров:
  - единый интерфейс text completion / structured output;
  - адаптер OpenAI;
  - адаптер второго провайдера;
  - единый слой ретраев, таймаутов и логирования ошибок.
- Для второго провайдера предусмотреть:
  - отдельный API key;
  - healthcheck/валидатор конфигурации;
  - fallback обратно на OpenAI для критичных сценариев.
- До включения второго провайдера в проде проверить:
  - совместимость structured output;
  - качество на интентах, анализе переписки и обычных ответах;
  - поведение при rate limits / timeout / provider outage.

## Model Presets

- Добавить именованные пресеты моделей, которые можно переключать из админки без ручного редактирования всех `OPENAI_MODEL_*`.
- Первый релиз UI включает только рабочие GPT-пресеты:
  - `GPT Max`
  - `GPT Balanced`
  - `GPT Budget`
- Hybrid-пресеты не входят в первый релиз UI:
  - `Hybrid DeepSeek + GPT`
  - `Hybrid Gemini + GPT`
- Для v1 список model keys, metadata, fallback и GPT-пресеты должны жить в одном общем data-only registry, который читают runtime и admin-panel.
- Отдельный env-ключ вроде `OPENAI_MODEL_PRESET` не вводить.
- Источник истины для активного пресета — фактические `OPENAI_MODEL_*`, а не отдельная persisted-метка.
- Для каждого пресета хранить:
  - полный набор model-полей;
  - описание;
  - метки риска / цены / качества.
- Поведение v1:
  - выбор пресета в админке заполняет форму как черновик;
  - реальные env-значения меняются только после `Save` / `Save All`;
  - UI пресетов живёт отдельным нижним блоком во вкладке `Настройки`;
  - ручные overrides редактируются через раскрывающийся advanced-блок, а не в общей секции настроек;
  - после применения пользователь может вручную переопределять отдельные поля;
  - в UI должно быть видно, что изменено вручную поверх выбранного пресета;
  - если значения больше не совпадают ни с одним пресетом, секция считается `Custom`.
- Для будущих hybrid-пресетов заранее держать контракт provider-aware preset schema:
  - provider + model по задачам;
  - fallback-политика на OpenAI;
  - документированный список hybrid-пресетов и покрываемых ими task-ролей.
