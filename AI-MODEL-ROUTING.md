# Модели и стоимость API

Обновлено 2026-10-26. Источник маршрутов — `admin-panel/src/ai-model-presets.json`; runtime и админка читают один реестр. Активный пресет выбирается через `bot_settings.AI_MODEL_PRESET`, затем ENV; default — `gpt-balanced`. API может использовать собственный scoped preset. Обновление кода не переписывает сохранённый выбор.

## Пользовательское управление

Основной интерфейс — два предпочтения: стоимость (`low/medium/high`), качество (`standard/high`). Сервер показывает план по подключённым ресурсам. Подключение LM Studio и включение локального/гибридного режима вынесены в отдельный блок. Остальные ручные профили доступны в дополнительных настройках; существующие установки не переключаются автоматически при обновлении. [Настройки и API](docs/model-preferences.md).

## Распределение без Astra

GPT-маршруты используют **GPT-6 Luna** (`gpt-6-luna`) и **GPT-6.1 Sol** (`gpt-6.1-sol`). Быстрый первый ответ, классификация, проверки, извлечение фактов и анализ сообщений во всех GPT-режимах — Luna с `none`. Изображения, vision, аудио, embeddings и локальные роли не мигрируются вместе с текстом.

| GPT-режим | Обычный диалог | Выбор инструментов | Сложный итоговый ответ | Консолидация памяти |
| --- | --- | --- | --- | --- |
| Экономный (`gpt-lean`) | Luna · none | Luna · low | Luna · low | Luna · low |
| Баланс, default (`gpt-balanced`) | Luna · none | Luna · low | Sol · low | Luna · low |
| Максимум качества (`gpt-max`) | Sol · low | Sol · low | Sol · low | Sol · low |

`none` выключает рассуждение, `low` ограничивает его интенсивность. Уровень задан рядом с моделью в `generation.reasoningEffort` и передаётся как в Chat Completions, так и в Responses. Максимальный профиль отличается более частым использованием Sol и большими лимитами; скрытого повышения до Astra нет.

В GPT-частях гибридов прежние nano/mini заменены Luna, полная GPT-5.4 — Sol. Gemini, GLM и LM Studio сохраняют свои основные модели и provider-pure ограничения. Экспериментальный OpenRouter Auto продолжает выбирать модель на стороне OpenRouter: у него отдельное распределение и переменная цена, поэтому он не является способом гарантировать стоимость двух фиксированных GPT-моделей.

## Назначение маршрутов

| Операция | Маршрут |
| --- | --- |
| Первый ответ вместе с оценкой запроса | `fastDialogue` |
| Короткие проверки, метки, эмоции, фильтры | `lightweightText`, `intentDedup` |
| Intent, параметры запроса и оценка сложности | `intentClassification` |
| Выбор и последовательность инструментов, включая legacy-планировщик | `runtimePlanning` |
| Обычный ответ с контекстом | `conversation` |
| Сложный синтез, противоречия памяти, портреты, глубокий анализ | `complexReasoning` |
| Извлечение фактов с автором и evidence | `memoryExtraction` |
| Консолидация глав памяти | `memoryConsolidation` |
| Анализ сообщений и приватные циклы Kira Life | `messageAnalysis` |
| Поиск, подготовка браузерных полей, vision, векторы, аудио | Специализированные маршруты |

Классификатор одновременно возвращает `details.responseComplexity`: расчёты, код, сравнения с ограничениями, сложный анализ получают `complex`. Разговорный агент выбирает `complexReasoning` по этому сигналу, составным намерениям или медицинскому контексту. Длина истории сама по себе не повышает модель. Отдельного платного классификатора сложности нет.

Фоновый разбор переиспользует подготовленную память без принудительного цикла инструментов, если достаточно синтеза. Актуальные сведения по-прежнему требуют поиска, составные запросы — выполнения всех действий. Подробнее: [быстрый диалог](docs/fast-dialogue.md).

## Совместимость API

- Luna по умолчанию у провайдера использует `medium`; runtime явно задаёт `none` либо `low` согласно задаче.
- Sol не поддерживает `none`/`minimal`: минимальный выбранный уровень — `low`.
- При reasoning выше `none` OpenAI-адаптер удаляет `temperature`, `top_p`, `top_logprobs`, а в Chat Completions ещё `logprobs`; в Responses убирает несовместимый logprobs item из `include`.
- Нативный function calling с рассуждением требует Responses. Для Sol нативные tools в Chat Completions запрещены вообще; Luna разрешает их только с `none`. Неподдерживаемый запрос отклоняется до отправки. Ядро Киры возвращает JSON-план без нативного `tools` в Chat Completions, поэтому сохраняет текущий контракт. Веб-поиск уже использует Responses.
- Старый `prompt_cache_retention`, если передан, заменяется на `prompt_cache_options.ttl=30m`; явный новый параметр сохраняется. Дополнительные cache-write запросы runtime не создаёт.
- Старые модели, конфигурация gateway и параметры других провайдеров не переписываются адаптером GPT-6.

Источники: [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [миграция GPT-6](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#migration-quickstart). Название страницы руководства не означает использование Astra в конфигурации.

## Лимиты и fallback

`outputTokenLimits` задаёт потолок одного вызова. Он действует на Chat Completions/Responses, retry, same-provider degradation и JSON fallback. Меньший лимит caller сохраняется; лимит reasoning-модели включает и токены рассуждения.

| Маршрут | Экономный | Баланс и облачные гибриды/full | Максимум качества |
| --- | ---: | ---: | ---: |
| `fastDialogue` | 1536 | 1536 | 1536 |
| `defaultText` | 2048 | 4096 | 8192 |
| `conversation` | 1536 | 3072 | 8192 |
| `runtimePlanning` | 3072 | 4096 | 8192 |
| `complexReasoning` | 4096 | 8192 | 16384 |

Локальные вызовы сохраняют лимиты и рассуждение из настроек ролей LM Studio. Ограничения остальных операций, включая извлечение и консолидацию фактов, остаются у вызывающего кода. Входная память не сокращается этим потолком. Лимит одного ответа не является суточным денежным бюджетом; автоматический платный фон отдельно управляется `BUDGET_MODE` и флагами функций.

Текстовый fallback — Luna: `low` для сложного ответа, планирования и консолидации, `none` для остальных задач. Сбой не повышает экономный режим до Sol/Astra. Fallback vision/embedding/audio сохранён. True-full Gemini/GLM/local не получает скрытого перехода на GPT. SDK-повторы отключены, retry управляется runtime; итоговые расходы включают все фактические попытки.

## Тарифы и ожидаемая экономия

Сверено с OpenAI Docs 2026-10-26. USD за 1 млн токенов при Standard и коротком контексте, без cache-write, инструментов и региональных надбавок:

| Модель | Вход | Выход | Источник |
| --- | ---: | ---: | --- |
| GPT-6 Luna | 0.10 | 0.50 | [OpenAI](https://developers.openai.com/api/docs/models/gpt-6-luna) |
| GPT-6.1 Sol | 2.00 | 10.00 | [OpenAI](https://developers.openai.com/api/docs/models/gpt-6.1-sol) |
| Прежняя GPT-5.4 nano | 0.20 | 1.25 | [OpenAI](https://developers.openai.com/api/docs/models/gpt-5.4-nano) |
| Прежняя GPT-5.4 mini | 0.75 | 4.50 | [OpenAI](https://developers.openai.com/api/docs/models/gpt-5.4-mini) |
| Прежняя GPT-5.4 | 2.50 | 15.00 | [OpenAI](https://developers.openai.com/api/docs/models/gpt-5.4) |

При одинаковом количестве токенов Luna дешевле nano на 50% по входу и 60% по выходу; дешевле mini примерно на 87% и 89%. Sol дешевле полной GPT-5.4 на 20% и 33%. Это сравнение тарифов, а не обещание снижения всего счёта: reasoning, cache writes, повторы, длина ответа и тариф gateway могут изменить итог. Качество более дешёвой модели на фактах памяти и составных задачах нужно оценивать отдельно.

## Проверка перед запуском

При локальном запуске минимальные запросы Luna/Sol через настроенный gateway прошли для Chat Completions, Luna также проверена через Responses. Это проверка транспорта, не оценка качества сложных задач. Наличие модели в публичной документации не гарантирует её доступность у другого gateway.

Синтетические проверки проверяют фактические тела запросов к SDK: выбранные model ID, reasoning, лимиты, фильтрацию параметров, endpoints и fallback. Они дополняют тесты составных задач, памяти, подтверждений, изоляции каналов и восстановления. До эксплуатации следует проверить две модели через рабочий gateway и сравнить одинаковые вопросы по качеству, задержке и фактическому usage. История логов и тестовые аналитические fixtures с прежними model ID сохраняются.
