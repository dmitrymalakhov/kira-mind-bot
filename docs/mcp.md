# MCP в Kira Mind

Кира получает данные и выполняет разрешённые действия через MCP в Telegram и личном API. Запрос проходит обычное ядро с журналом операций и проверками владельца. Пример: «Через Money Maker найди новости по тикеру за неделю и приведи источники».

## Подключение в админке

1. В Money Maker открой **Настройки аккаунта → Подключения по MCP** (`<origin>/account-settings#mcp-tokens`) и выпусти отдельный токен для Киры на 7, 30 или 90 дней. Скопируй показанный один раз токен и адрес MCP.
2. В админке Киры открой **Настройки → Подключения → Money Maker · MCP**. Вставь адрес и токен, нажми «Проверить связь», затем «Сохранить подключение». Работает и общая кнопка сохранения; переходы по разделам сохраняют черновик.
3. Для ротации выпусти новый токен в Money Maker, замени его в Кире и после проверки отзови старый в Money Maker. Пустое поле сохраняет текущий токен; при смене адреса токен нужно вставить заново.
4. «Отключить» удаляет подключение в Кире. Кнопка «Управлять токенами» открывает Money Maker: там видны срок действия, последнее использование и отзыв самого токена.

Сохранённый токен не возвращается в браузер. Проверка связи выполняет только handshake и discovery, не запускает аналитику. Настройки применяются без перезапуска. В account mode админка использует доверенную привязку локально импортированного аккаунта и отказывается писать в общий runtime при отсутствии такой привязки.

## Настройка

Конфигурация — `mcp.json` внутри `KIRA_RUNTIME_DATA_DIR`. В Compose это `/app/runtime-data/mcp.json`; на хосте — соответствующий смонтированный каталог. При прямом запуске без переменной используется `data/mcp.json`, а для собранного приложения — `dist/data/mcp.json`. Credentials хранятся только в локальном файле с правами `600`, вне Git.

В режиме нескольких аккаунтов каждому worker нужен собственный файл в его каталоге `data/`. Подключения оператора не наследуются tenant-ами. Доверенный локальный импорт переносит `mcp.json` существующего инстанса только в его собственный аккаунт после проверки владельца. Изменённый файл перечитывается без пересборки; уже начатая операция использует свой снимок подключения.

Скопируй [пример Money Maker](mcp.example.json), укажи HTTPS origin и действующий Bearer в локальной копии. Проверка вызывает только `initialize` и `tools/list`, без аналитики, AI и внешних действий:

```bash
npm run mcp:check -- --config runtime-data/mcp.json money-maker
```

| `transport` | Подключение |
| --- | --- |
| `http` | Стандартный MCP Streamable HTTP: `url`, необязательные `headers` |
| `jsonrpc` | POST-only JSON-RPC, например Money Maker; без SSE, session headers и replay |
| `stdio` | Локальный процесс: `command`, необязательные `args` и `env`; без shell |

Удалённые серверы требуют HTTPS; HTTP разрешён только для loopback и `host.docker.internal`. Credentials в URL запрещены, redirects не выполняются. Таймаут всей операции — `timeoutMs`, от 100 до 60000 мс, по умолчанию 30000. После операции соединение и stdio-процесс закрываются.

`tools` — список разрешённых имён с эффектом `read` либо `external`. Неизвестные инструменты не вызываются; `readOnlyHint` не выдаёт права. `fixedArguments` задаёт аргументы подключения, которые модель не может переопределить. Секреты хранятся в заголовках/окружении подключения, не в аргументах.

Доступ — только владельцу в личном канале. Чтение работает и в отложенном анализе; внешнее изменение требует явного поручения, подтверждения точных аргументов и write-ahead квитанции. При потерянном ответе результат изменения — `unknown`, автоматического повтора нет. Регулярная задача, ожидающая подтверждения, приостанавливается. Данные MCP не расширяют исходное поручение.

## Money Maker

Подключение сверено с `docs/mcp.md` проекта Money Maker, полученным через Codex на MacBook Pro 27 октября 2026 года. Шлюз использует `POST <origin>/api/stocks/money-maker/mcp`, Bearer Money Maker ID и протокол `2024-11-05`. Ответ — JSON; `notifications/initialized` возвращает HTTP 204. Выбирай `jsonrpc`.

Исходная версия сервера принимает пользовательский access token; обычный service/machine токен с `market:read` не разрешает MCP. Для постоянного подключения подготовлено управление отдельными MCP-токенами в Money Maker и его ID: эти изменения должны быть установлены на сервере перед выпуском рабочего токена. Клиент не обходит серверную политику.

Установка серверной части выполняется в порядке: Money Maker ID с миграцией `004_personal_mcp_tokens.sql`, затем Money Maker. Значение токена возвращается один раз, ID хранит SHA-256; отзыв, истечение и отключение владельца проверяются при обращениях. Сам токен не может выпускать или отзывать credentials. Первый рабочий токен выпускается после установки этих изменений.

В примере разрешены 12 инструментов персонального MCP-токена: свечи, цена, индикаторы, технический анализ, режим рынка, новости, отчётность и календарь. История решений, чужие данные и торговые команды этим токеном недоступны. Схемы читаются через `tools/list`. Идентификатор клиента задаёт сервер; Кира не передаёт `requesterAgentId` и фиксирует только `responseMode=full`.

Для новостей фиксируется `responseMode=full`: текст статьи находится в `structuredContent.callResults[]` с `capabilityId=search_news` → `result.data.links[].text`. Текст может отсутствовать или быть фрагментом; `content[].text` — сводка. StructuredContent передаётся Кире в ограниченном бюджете с явной отметкой сокращения. Верхний `query` задаёт вопрос брокеру, а `params.query` — поисковую строку.

Инструменты цены, индикаторов и режима рынка требуют реальные входные `candles`, а не один тикер. `resolution=partial` и gaps сохраняют ограничения ответа. `isError=true` — ошибка даже при HTTP 200.

## Инструменты ядра

`mcp.listServers`, `mcp.listTools`, `mcp.callReadTool`, `mcp.callTool`, `mcp.listResources`, `mcp.readResource`. Каталог ограничен по размеру: фильтр `query`, локальные страницы `nextOffset`, затем серверный `nextCursor`. `argumentsJson` проверяется по реальной JSON Schema до вызова. Server prompts, sampling, roots и elicitation не включены.

Нужен `KIRA_ORCHESTRATION_MODE=skills`. Legacy orchestration MCP не вызывает.
