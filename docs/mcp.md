# MCP в Kira Mind

Кира получает данные и выполняет разрешённые действия через MCP в Telegram и личном API. Запрос проходит обычное ядро с журналом операций и проверками владельца. Называть MCP не обязательно: Кира выбирает подключённые сервисы по смыслу просьбы, описанию подключения и именам разрешённых инструментов. Например, при подключённом сервисе рыночных данных можно попросить: «Покажи текущий часовой тренд по SBER и новости за неделю».

Один запрос может использовать несколько MCP: «Найди товары с низким остатком и покажи ожидаемые поставки для каждого». При наличии соответствующих подключений Кира читает остатки, получает реальные коды товаров и ищет поставки по этим кодам в другом сервисе. Независимые чтения могут выполняться параллельно; зависимые аргументы составляются после получения предыдущего результата. В контексте обработки и квитанциях сохраняется ID сервиса для каждого результата.

Общее объяснение («что такое RSI») и вопрос о сохранённом разговоре сами по себе не требуют MCP из-за общей темы. Если пользователь явно выбрал источник, Кира соблюдает этот выбор. При неоднозначных данных или идентификаторах может понадобиться уточнение.

## Подключение в админке

1. Открой **Настройки → Подключения → MCP-серверы**. Список показывает все подключения из `mcp.json`, включая существующий Money Maker. Можно настроить до 16 серверов.
2. Нажми **Добавить MCP**, задай уникальный ID, описание возможностей для Киры и транспорт: Streamable HTTP, POST JSON-RPC или stdio. Для HTTP укажи произвольный адрес MCP; для stdio — команду, JSON-массив аргументов и переменные окружения.
3. Настрой авторизацию, если она нужна: заголовок `Authorization` со значением `Bearer <токен>`, другие заголовки или OAuth client credentials. Серверы без авторизации тоже поддерживаются. Сохранённые значения заголовков, env и client secret скрыты; пустое поле сохраняет их, удаление строки удаляет значение. При смене адреса, транспорта, команды/аргументов либо OAuth-клиента секреты нужно ввести заново.
4. Нажми **Проверить связь**. Проверка выполняет handshake и читает постраничный каталог, без вызова инструментов. Новые инструменты по умолчанию выключены; для каждого выбери **Чтение** или **Действие с подтверждением**. Имена можно добавить вручную. Успех проверки не означает сохранение или выдачу разрешений.
5. Нажми **Сохранить подключение** или общую кнопку сохранения. Переходы по разделам сохраняют черновик. Дополнительные параметры включают таймаут и фиксированные аргументы. **Отключить** удаляет только выбранный MCP из Киры.

**Money Maker** — готовый шаблон в этом же списке: POST JSON-RPC, `responseMode=full` и 12 разрешённых инструментов чтения. В Money Maker открой **Настройки аккаунта → Подключения по MCP** (`<origin>/account-settings#mcp-tokens`), выпусти отдельный токен для Киры и скопируй адрес MCP. Выбери шаблон, вставь адрес и `Bearer <токен>` в значение заголовка `Authorization`, проверь и сохрани. Кнопка **Токены Money Maker** открывает управление сроком и отзывом токенов. При ротации сначала сохрани и проверь новый токен, затем отзови старый у поставщика.

Настройки применяются без перезапуска. Секреты не возвращаются в браузер; отключение в Кире не отзывает токен у поставщика. В account mode админка использует доверенную привязку локально импортированного аккаунта и отказывается писать в общий runtime при отсутствии такой привязки. Команда stdio и её зависимости должны быть установлены в окружении Киры и админки; это пути внутри контейнеров при работе в Docker. Интерактивная OAuth-авторизация и устаревший HTTP+SSE transport не поддерживаются.

Для автоматического выбора пиши короткое предметное описание: какие данные доступны и по каким ключам их можно связать с другими сервисами. Например: «Остатки товаров по складам, поиск по SKU» и «Ожидаемые поставки по SKU». Каталог маршрутизации читается локально, без обращения ко всем серверам на каждую реплику. Он ограничен общим бюджетом; `omittedTools` отмечает сокращённый список имён. Реальные описания и схемы выбранных инструментов Кира получает через `tools/list` перед вызовом.

Существующий JSON-проход классификации возвращает `details.mcpServers` вместе с режимом доступа; отдельного AI-роутера нет. ID проверяются по локальной конфигурации, повторы и неизвестные значения удаляются. Планировщик может сразу запросить схемы выбранных сервисов, а при пустом или недостаточном выборе — уточнить каталог. Список источников сам по себе даёт только сигнал чтения: изменение требует отдельного `mcpAccess=write`, разрешённого инструмента и подтверждения точных аргументов.

## Настройка

Конфигурация — `mcp.json` внутри `KIRA_RUNTIME_DATA_DIR`. В Compose это `/app/runtime-data/mcp.json`; на хосте — соответствующий смонтированный каталог. При прямом запуске без переменной используется `data/mcp.json`, а для собранного приложения — `dist/data/mcp.json`. Credentials хранятся только в локальном файле с правами `600`, вне Git.

В режиме нескольких аккаунтов каждому worker нужен собственный файл в его каталоге `data/`. Подключения оператора не наследуются tenant-ами. Доверенный локальный импорт переносит `mcp.json` существующего инстанса только в его собственный аккаунт после проверки владельца. Изменённый файл перечитывается без пересборки; уже начатая операция использует свой снимок подключения.

Скопируй [пример Money Maker](mcp.example.json), укажи HTTPS origin и действующий Bearer в локальной копии. Проверка вызывает только `initialize` и `tools/list`, без аналитики, AI и внешних действий:

```bash
npm run mcp:check -- --config runtime-data/mcp.json money-maker
```

| `transport` | Подключение |
| --- | --- |
| `http` | Стандартный MCP Streamable HTTP: `url`, необязательные `headers` |
| `jsonrpc` | POST-only JSON-RPC, например Money Maker; без SSE, session headers и replay |
| `stdio` | Локальный процесс: `command`, необязательные `args` и `env`; без shell |

Удалённые серверы требуют HTTPS; HTTP разрешён только для loopback и `host.docker.internal`. Credentials в URL запрещены, redirects не выполняются. Таймаут всей операции — `timeoutMs`, от 100 до 60000 мс, по умолчанию 30000. После операции соединение и stdio-процесс закрываются.

`tools` — список разрешённых имён с эффектом `read` либо `external`. Неизвестные инструменты не вызываются; `readOnlyHint` не выдаёт права. `fixedArguments` задаёт аргументы подключения, которые модель не может переопределить. Секреты хранятся в заголовках/окружении подключения, не в аргументах.

Доступ — только владельцу в личном канале. Чтение работает и в отложенном анализе; внешнее изменение требует явного поручения, подтверждения точных аргументов и write-ahead квитанции. При потерянном ответе результат изменения — `unknown`, автоматического повтора нет. Регулярная задача, ожидающая подтверждения, приостанавливается. Данные MCP не расширяют исходное поручение.

## Money Maker

Подключение сверено с `docs/mcp.md` проекта Money Maker, полученным через Codex на MacBook Pro 27 октября 2026 года. Шлюз использует `POST <origin>/api/stocks/money-maker/mcp`, Bearer Money Maker ID и протокол `2024-11-05`. Ответ — JSON; `notifications/initialized` возвращает HTTP 204. Выбирай `jsonrpc`.

Для постоянного подключения используются отдельные MCP-токены Money Maker ID. Обычный service/machine токен с `market:read` не разрешает MCP. Серверную поддержку персональных токенов устанавливают до выпуска рабочего токена; клиент не обходит серверную политику.

Установка серверной части выполняется в порядке: Money Maker ID с миграцией `004_personal_mcp_tokens.sql`, затем Money Maker. Значение токена возвращается один раз, ID хранит SHA-256; отзыв, истечение и отключение владельца проверяются при обращениях. Сам токен не может выпускать или отзывать credentials. Первый рабочий токен выпускается после установки этих изменений.

В примере разрешены 12 инструментов персонального MCP-токена: свечи, цена, индикаторы, технический анализ, режим рынка, новости, отчётность и календарь. История решений, чужие данные и торговые команды этим токеном недоступны. Схемы читаются через `tools/list`. Идентификатор клиента задаёт сервер; Кира не передаёт `requesterAgentId` и фиксирует только `responseMode=full`.

Для новостей фиксируется `responseMode=full`: текст статьи находится в `structuredContent.callResults[]` с `capabilityId=search_news` → `result.data.links[].text`. Текст может отсутствовать или быть фрагментом; `content[].text` — сводка. StructuredContent передаётся Кире в ограниченном бюджете с явной отметкой сокращения. Верхний `query` задаёт вопрос брокеру, а `params.query` — поисковую строку.

Для цены, индикаторов и режима рынка нужны реальные свечи. Проверяй актуальные описания и `inputSchema`: при поддержке серверной загрузки передавай `ticker`/`figi` и допустимые `interval`/`limit`; для анализа выбирай инструмент, который сам загрузит данные, без копирования большого массива свечей через модель. В ответе сохраняются интервал, источник и время последних доступных закрытых свечей. Нулевые свечи и `resolution=missing` не позволяют утверждать тренд; `partial` и gaps сохраняют ограничения. `isError=true` — ошибка даже при HTTP 200. Технический JSON ошибки остаётся контекстом обработки, а пользователь получает короткое объяснение.

Версия Money Maker с серверным рыночным контекстом загружает данные для технических инструментов по `ticker`/`figi`. Например, `get_technical_decision_brief` принимает `{"ticker":"SBER","interval":"1h","lookback":80}` без массива `candles`. `stockName` не заменяет биржевой идентификатор. Для вопроса о тренде «сейчас» Кира использует часовой период, если пользователь не выбрал другой. Источник и свежесть передаются в `result.data.marketData`; для сырых свечей `get_candles` поддерживает `limit` до 200.

## Инструменты ядра

Запрошенный MCP-источник не подменяется вебом после ошибки. Явная просьба дополнительно сверить сведения в публичном вебе передаётся тем же классификатором как `details.mcpAllowWeb`; без неё веб и research для этого запроса недоступны. Веб-результат сам по себе не подтверждает получение данных MCP.

Большие ответы Money Maker сначала освобождаются от повторяющихся представлений `rolePayload` и `content`, затем ограничиваются по отдельным строкам и массивам. Свидетельства остаются валидным JSON с явной отметкой неполноты; источники, даты, статусы и доступный текст не отрезаются общим префиксом до `callResults`. Итоговый синтез не дублирует схемы каталога и сырые результаты в квитанциях поверх уже полученных свидетельств.

При сокращении длинного ряда сохраняются начало и конец с отметкой пропущенной середины: последние значения индикатора не заменяются давними точками. Для рыночных данных добавляются проверенные форматные подписи `marketTimesUTC` без изменения цифр исходного UTC: время закрытой свечи и время получения остаются разными полями. В новостях дата публикации не заменяет дату события; частичное покрытие отчётности не позволяет утверждать, что более нового отчёта нет.

`mcp.listServers`, `mcp.listTools`, `mcp.callReadTool`, `mcp.callTool`, `mcp.listResources`, `mcp.readResource`. Каталог ограничен по размеру: фильтр `query`, локальные страницы `nextOffset`, затем серверный `nextCursor`. `argumentsJson` проверяется по реальной JSON Schema до вызова. Server prompts, sampling, roots и elicitation не включены.

Нужен `KIRA_ORCHESTRATION_MODE=skills`. Legacy orchestration MCP не вызывает.

## Живая тестовая корзина

Режим `burst` делает 25 коротких read-only вызовов с отдельным handshake и сохраняет безопасные HTTP-статусы/остатки лимита. Он проверяет накладные расходы протокола без AI. HTTP 429 сообщает о лимите сервиса и безопасном `Retry-After`, 401/403 — об отказе авторизации; ошибка параметров JSON-RPC не подаётся как неисправный токен. Автоматический повтор не добавляется.

`scripts/evalMcpBasket.cjs` — операторская диагностика локального account mode. Она читает доверенную привязку импортированного аккаунта и его действующий MCP-config, создаёт временную синтетическую сессию и не использует историю, личную память или отправку в Telegram. `catalog` проверяет обнаружение; `direct` вызывает все 12 разрешённых инструментов и проверяет отказы; `dialogue` проходит настоящий `processMessage`, быстрый классификатор, планировщик и разговорный синтез. Диалоговый режим расходует обычный бюджет AI.

Запускай из корня репозитория, подставив контейнер своего Compose project:

```bash
mkdir -p runtime-data/diagnostics/mcp-audit
umask 077
docker exec -i <account-container> node - --mode direct \
  < scripts/evalMcpBasket.cjs > runtime-data/diagnostics/mcp-audit/direct.ndjson
docker exec -i <account-container> node - --mode dialogue \
  < scripts/evalMcpBasket.cjs > runtime-data/diagnostics/mcp-audit/dialogue.ndjson
```

Для короткого повторного прогона добавь `--ids trend-name-now,news,compare`. Флаг `--judge` добавляет один независимый AI-разбор готового ответа по фактическим свидетельствам каждого диалога через обычный маршрут `complexReasoning`; он дополняет ручную оценку и расходует AI-бюджет.

Отчёт хранится локально вне Git и маскирует credential подключения. `pass` означает прохождение технических проверок; `limited` — ответ источника `missing`/`partial`, а не полноту данных. Дополнительно оцени готовый текст: соответствие тикеру и периоду, время свечи, даты/ссылки, честное описание ограничений. Ни HTTP 200, ни правдоподобный ответ без вызова нужного источника не считаются успехом. Токен не выпускается, не отзывается и не меняется; при завершении временная сессия удаляется.
