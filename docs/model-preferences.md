# Настройки моделей

В админке откройте настройки моделей. Выберите два предпочтения и нажмите «Применить»:

- **Стоимость:** низкая, средняя или высокая. Задаёт класс моделей и предел одного ответа. Повторы, число запросов, поиск и входные токены также влияют на счёт; это не денежная квота.
- **Качество:** обычное или высокое. Для сложных задач меняет глубину рассуждения в пределах выбранного класса стоимости. Высокое качество при низкой стоимости не включает Sol или Astra.

Перед сохранением видны доступность сочетания и модели по задачам. Если своих подключений нет, используются доступные API сервиса.

В блоке «Свои локальные модели»:

1. Запустите Local Server в LM Studio. Сохраните адрес с `/v1`, начальную модель и токен (если включена авторизация). В Docker Desktop адрес компьютера — `host.docker.internal`, а не `localhost`. После изменения подключения пересоздайте контейнеры бота и админки; обычного рестарта недостаточно.
2. Нажмите «Обновить список», выберите модели для быстрых задач, анализа и глубокого рассуждения. Одну модель можно использовать во всех ролях. Сохранение ролей применяется в течение пяти секунд.
3. Включите локальный режим либо гибрид (сложный анализ через облачный API). Поиск, голос, изображения и embeddings сохраняют специализированные подключения. Автоматический выбор стоимости/качества снова включается кнопкой «Применить» в верхнем блоке.

Имена моделей не используются для определения их ограничений. Устаревшие переменные `KIRA_FREE_DIALOGUE_MODEL`, `LM_STUDIO_FREE_MODEL` и отметки `freeDialogue` больше не влияют на новые планы. Старые version-1 политики и фоновые снимки сохраняют точные маршруты и запрет fallback; чтение не меняет выбор пользователя. URL и ключи подключения настраивает оператор, они не принимаются от account API.

Старый сохранённый профиль продолжает работать до явного применения предпочтений. В дополнительных настройках можно вернуться к ручному выбору. Параметры локальных ролей меняются отдельно и продолжают действовать без переписывания памяти. Платные фоновые функции и максимальная экономия настраиваются отдельно: выбор стоимости сам по себе их не включает.

## API

`GET /api/v1/model-preferences` возвращает режим `automatic/manual`, предпочтения, действующий план, доступность 6 сочетаний и состояние подключений без ключей. Настройка действует в рамках аккаунта. Явный прежний режим приложения имеет приоритет только в его диалоге.

`PUT /api/v1/model-preferences`, с обычным Bearer текущего аккаунта:

```json
{"cost":"low","quality":"high"}
```

Другие поля, в том числе credentials, account/user IDs и произвольные model IDs, запрещены. Сервер проверяет ресурсы до записи; базовый профиль и полный план сохраняются одной атомарной операцией в `bot_settings`. Изменения подхватываются в течение пяти секунд. Фоновые продолжения используют снимок политики исходного сообщения. API не меняет профиль embeddings и не переиндексирует память.

## Короткий диалог

Точное «Ты тут?» получает короткое подтверждение без классификатора, retrieval или фонового задания. Приветствия и благодарности не становятся исследованием из-за ошибочного сигнала модели. Составные просьбы, пересылки, ответы на другие сообщения и активные подтверждения сохраняют обычную обработку. Отмена действительно долгой работы по-прежнему доступна через `/cancel_deep`; новая реплика останавливает старый разбор.
