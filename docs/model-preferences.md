# Настройки моделей

На странице «Модели» выберите уровень качества и нажмите «Применить»:

- **Обычное** — повседневный диалог, лёгкие модели и умеренные лимиты. Наименьший ожидаемый расход API среди трёх уровней.
- **Высокое** — более глубокий разбор сложных запросов, сильная модель подключается к сложному анализу. Стоимость выше обычного уровня.
- **Максимальное** — сильные модели для диалога и планирования, больше рассуждений и места для ответа. Наибольший ожидаемый расход, сложные ответы могут занимать больше времени. Astra не используется.

Рассуждения тоже расходуют оплачиваемые выходные токены: [OpenAI Docs](https://developers.openai.com/api/docs/guides/reasoning). Уровень — профиль обработки, а не обещание точной цены или денежная квота. Итог зависит от входного контекста, длины ответа и инструментов. Фоновые функции управляются отдельно. Если доступен только другой провайдер, используются его модели и лимиты уровня; предпросмотр сообщает об ограниченном каталоге.

Старый сохранённый план не пересобирается при обновлении. Его cost-метаданные отображаются как уровень (low→обычное, medium→высокое, high→максимальное), но точные модели, лимиты и запрет fallback сохраняются до явного применения нового выбора.

В блоке «Свои локальные модели»:

1. Запустите Local Server в LM Studio. На странице «Модели» сохраните адрес с `/v1` и начальную модель. Токен, если включена авторизация, задаётся на странице «Ключи и подключения». В Docker Desktop адрес компьютера — `host.docker.internal`, а не `localhost`. После изменения подключения пересоздайте контейнеры бота и админки; обычного рестарта недостаточно.
2. Нажмите «Обновить список», выберите модели для быстрых задач, анализа и глубокого рассуждения. Одну модель можно использовать во всех ролях. Сохранение ролей применяется в течение пяти секунд.
3. Включите локальный режим либо гибрид (сложный анализ через облачный API). Поиск, голос, изображения и embeddings сохраняют специализированные подключения. Автоматический выбор качества снова включается кнопкой «Применить» в верхнем блоке.

Имена моделей не используются для определения их ограничений. Устаревшие переменные `KIRA_FREE_DIALOGUE_MODEL`, `LM_STUDIO_FREE_MODEL` и отметки `freeDialogue` больше не влияют на новые планы. Старые version-1 политики и фоновые снимки сохраняют точные маршруты и запрет fallback; чтение не меняет выбор пользователя. URL и ключи подключения настраивает оператор, они не принимаются от account API.

Старый сохранённый профиль продолжает работать до явного применения предпочтений. В дополнительных настройках можно вернуться к ручному выбору. Параметры локальных ролей меняются отдельно и продолжают действовать без переписывания памяти. Платные фоновые функции и максимальная экономия настраиваются отдельно: выбор качества сам по себе их не включает.

## API

`GET /api/v1/model-preferences` возвращает режим `automatic/manual`, предпочтения, действующий план, доступность 3 уровней и состояние подключений без ключей. Настройка действует в рамках аккаунта. Явный прежний режим приложения имеет приоритет только в его диалоге.

`PUT /api/v1/model-preferences`, с обычным Bearer текущего аккаунта:

```json
{"quality":"high"}
```

Другие поля, включая прежний `cost`, credentials, account/user IDs и произвольные model IDs, запрещены. Сервер проверяет ресурсы до записи; базовый профиль и полный план сохраняются одной атомарной операцией в `bot_settings`. Изменения подхватываются в течение пяти секунд. Новые планы имеют version 2; прежние version-1 снимки читаются совместимо. Фоновые продолжения используют снимок политики исходного сообщения. API не меняет профиль embeddings и не переиндексирует память.

## Короткий диалог

Точное «Ты тут?» получает короткое подтверждение без классификатора, retrieval или фонового задания. Приветствия и благодарности не становятся исследованием из-за ошибочного сигнала модели. Составные просьбы, пересылки, ответы на другие сообщения и активные подтверждения сохраняют обычную обработку. Отмена действительно долгой работы по-прежнему доступна через `/cancel_deep`; новая реплика останавливает старый разбор.

## Страницы настроек

- **Модели**: уровень качества, локальные роли и режим, генерация изображений, модель и голос озвучивания. Отдельный прокси изображений задаётся здесь, если они должны использовать другое подключение.
- **Ключи и подключения**: credentials AI, озвучивания, Telegram и других сервисов на одной странице. Переключатель прокси OpenAI показывает URL только при включении. Уже заданный нестандартный `OPENAI_BASE_URL` сохраняется и отображается включённым; выключение сохраняет пустой адрес для прямого подключения после пересоздания контейнеров.
- **Фон и экономия**: самостоятельные функции и приостановка AI-фона.
- **Система**: база, параметры памяти, общие ограничения и расписание. Референс внешности — в «Личность».

Отключение прокси не меняет ключ API: для прямого подключения должен подходить ключ OpenAI. Изменения ключей и адресов требуют пересоздания контейнеров; обычный рестарт не перечитывает Docker env.
