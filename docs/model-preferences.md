# Настройки моделей

В блоке «Как Кира выбирает модели» доступны две стратегии:

- **Автоматически · API** — локальные модели в этом режиме не используются. Кира распределяет задачи по выбранному качеству и API. По умолчанию — API, выбранные системой. Можно закрепить OpenAI, Gemini, Z.ai или OpenRouter + OpenAI, если необходимые подключения доступны. Явный выбор API не подменяется другим провайдером при ошибке. OpenRouter Auto управляет моделью диалога самостоятельно; для служебных задач этого варианта требуется OpenAI.
- **Custom** — открывает окно редактора: сначала один провайдер, затем его модели, лимиты и рассуждения для каждой текстовой задачи. Выбираются только модели из подключённого каталога проекта и LM Studio. Поиск, vision и голос используют сервисные подключения выбранного провайдера (для LM Studio/OpenRouter — отдельные API); действующий профиль векторов памяти не меняется. Текстовые маршруты закрепляются без автоматического fallback. Рассуждения применяются в пределах возможностей модели.

Три уровня качества:

- **Обычное** — лёгкие модели и умеренные лимиты для повседневных задач; наименьший ожидаемый расход внутри выбранного API.
- **Высокое** — сильная модель для сложного анализа; расход выше обычного.
- **Максимальное** — сильные модели также для диалога и планирования, увеличенные лимиты и рассуждения, где поддерживаются; наибольший ожидаемый расход.

Сравнение стоимости относительное, между уровнями одного API. Сервис не вычисляет денежный тариф и не обещает межпровайдерный рейтинг качества. Для точной цены нужны действующие тарифы провайдера и фактическое использование. Рассуждения расходуют оплачиваемые выходные токены: [OpenAI Docs](https://developers.openai.com/api/docs/guides/reasoning). Уровень не является квотой и не включает фоновые функции. Astra в автоматических профилях не используется.

Блок «Сейчас работает» показывает сохранённую стратегию отдельно от выбранных, но ещё не применённых настроек. В автоматическом режиме тумблера локальных моделей нет: кнопка «Настроить локальные модели в Custom» открывает редактор Custom. Тумблер «Использовать локальные модели» находится внутри этого редактора и выбирает LM Studio. Переключение применяется после «Сохранить стратегию Custom»; отмена оставляет текущую стратегию. Отключение тумблера предлагает заменить локальные задачи API-моделями, также с явным сохранением.

Для подключения включите Local Server в LM Studio. В редакторе Custom включите локальные модели, сохраните адрес с `/v1` и начальную модель. Токен, если нужен, задаётся в «Ключи и подключения». Для Docker Desktop используйте `host.docker.internal`. Изменение URL и токена требует пересоздания контейнеров бота и админки. Затем обновите каталог и выберите модели. Можно назначить одну модель всем задачам. Параметры стратегии начинают действовать в течение пяти секунд.

Существующие ручные профили показаны как Custom, но при чтении не преобразуются. Если текстовые задачи используют нескольких провайдеров, редактор требует явно выбрать одного перед сохранением нового плана. До сохранения они продолжают работать с прежними ролями/fallback. Version-1/2 политики и фоновые снимки сохраняют точные модели, параметры, лимиты и запреты fallback. Пересборка — только после сохранения. URL, ключи и identity не принимаются через API стратегии.

## API

`GET /api/v1/model-preferences` возвращает режим `automatic/manual/custom`, предпочтения, действующий план, три автоматических уровня, `providerPlans`, список `providers`, подключённый `catalog` и локальные роли без credentials. `manual` — совместимый старый профиль, в UI он представлен как Custom. Настройка ограничена аккаунтом; явный режим приложения имеет приоритет только в его диалоге.

Автоматическая стратегия, `PUT /api/v1/model-preferences`:

```json
{"quality":"high","provider":"openai"}
```

`provider` необязателен; отсутствие или `auto` означает выбор системы. Разрешены `standard/high/maximum` и `auto/openai/gemini/zai/openrouter`.

Custom: `{mode:"custom", quality:"high", provider:"openai", routes:<все TEXT_TASKS>}`. Один провайдер (`openai/gemini/zai/openrouter/lmstudio`) применяется ко всем текстовым задачам. Каждый маршрут принимает строго `{model,maxTokens,reasoningEffort}`; отдельный provider внутри маршрута и прежний presetName не принимаются. Модель проверяется по подключённому каталогу выбранного провайдера, лимит 32–16384, рассуждения `none/low/medium/high`. Служебные подключения сервер определяет по провайдеру; они и действующий профиль памяти проверяются до записи. Локальные роли и произвольные ENV-ссылки не принимаются; сохраняется точный ID модели и её параметры.

План и базовый профиль записываются одной атомарной SQL-операцией. Новые явные API/Custom-планы — version 3; прежний запрос только с quality продолжает создавать совместимый version 2. Перед откатом на старый runtime сначала включите поддерживаемый им ручной профиль в текущей версии: старый runtime не понимает version 3.
