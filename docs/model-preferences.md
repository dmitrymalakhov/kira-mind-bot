# Настройки моделей

В блоке «Диалог и мышление» доступны две стратегии:

- **Автобалансировка** — Кира распределяет этапы задачи между моделями подключённых провайдеров по роли этапа, качеству, нагрузке и технической доступности. В общем пуле доступны GPT, Gemini, GLM и Kimi через OpenRouter. Можно ограничить участников и явно включить настроенные локальные роли LM Studio. По умолчанию локальные модели исключены. При техническом отказе замена ограничена сохранённым пулом; отказ модерации или структурированный отказ модели останавливает запрос, включая JSON repair. Можно по-прежнему закрепить OpenAI, Gemini, Z.ai или OpenRouter/Kimi без межпровайдерной замены. Новые стратегии OpenRouter распределяют роли между несколькими моделями через один ключ. Прямой Kimi — отдельный участник с ключом Moonshot (`KIMI_API_KEY`), Pro и Highspeed. Сохранённые прежние гибридные маршруты читаются без замены.
- **Custom** — открывает окно редактора: сначала один провайдер, затем его модели, лимиты и рассуждения для каждой текстовой задачи. Выбираются только модели из подключённого каталога проекта и LM Studio. Сервисные маршруты определяет базовый профиль. Доступность поиска, голоса и векторов показывается отдельно; новые Kimi/OpenRouter-профили используют vision того же API. Действующий профиль векторов памяти не меняется. Текстовые маршруты закрепляются без автоматического fallback. Рассуждения применяются в пределах возможностей модели.

Три уровня качества:

- **Обычное** — лёгкие модели и умеренные лимиты для повседневных задач; наименьший ожидаемый расход внутри выбранного API.
- **Высокое** — сильная модель для сложного анализа; расход выше обычного.
- **Максимальное** — сильные модели также для диалога и планирования, увеличенные лимиты и рассуждения, где поддерживаются; наибольший ожидаемый расход.

Сравнение стоимости относительное, между уровнями одного API. Сервис не вычисляет денежный тариф и не обещает межпровайдерный рейтинг качества. Для точной цены нужны действующие тарифы провайдера и фактическое использование. Рассуждения расходуют оплачиваемые выходные токены: [OpenAI Docs](https://developers.openai.com/api/docs/guides/reasoning). Уровень не является квотой и не включает фоновые функции. Astra в автоматических профилях не используется.

Блок «Сейчас работает» показывает сохранённую стратегию отдельно от черновика. В автобалансировке LM Studio включается флажком участника пула и применяется кнопкой «Применить»; сохраняются точные ID и параметры доступных локальных ролей. Кнопка настройки локальных моделей открывает редактор Custom с подключением; его отмена оставляет текущую стратегию. Тумблер внутри Custom закрепляет LM Studio для всех текстовых задач.

Для подключения включите Local Server в LM Studio. В редакторе Custom включите локальные модели, сохраните адрес с `/v1` и начальную модель. Токен, если нужен, задаётся в «Подключения». Для Docker Desktop используйте `host.docker.internal`. Изменение URL и токена требует пересоздания контейнеров бота и админки. Затем обновите каталог и выберите модели. Можно назначить одну модель всем задачам. Параметры стратегии начинают действовать в течение пяти секунд.

Существующие ручные профили показаны как Custom, но при чтении не преобразуются. Если текстовые задачи используют нескольких провайдеров, редактор требует явно выбрать одного перед сохранением нового плана. До сохранения они продолжают работать с прежними ролями/fallback. Version-1/2 политики и фоновые снимки сохраняют точные модели, параметры, лимиты и запреты fallback. Пересборка — только после сохранения. URL, ключи и identity не принимаются через API стратегии.

## API

`GET /api/v1/model-preferences` возвращает режим `automatic/manual/custom`, предпочтения, действующий план, три автоматических уровня, `providerPlans`, `poolPlans` (пулы для предпросмотра, включая доступные локальные роли), список `providers`, подключённый `catalog` и локальные роли без credentials. `manual` — совместимый старый профиль, в UI он представлен как Custom. Настройка ограничена аккаунтом; явный режим приложения имеет приоритет только в его диалоге.

Мобильный ответ дополнительно содержит `qualityLevels`, `textTasks`, `appOverride` и `effectivePlan`: маршруты аккаунта и текущего app override с реальным provider/model/location и допустимыми fallback, отдельно `memoryEmbedding`. У недоступных вариантов есть безопасные `unavailableCode/unavailableReason`, без ENV-имён. `recipientDisclosure.complete:false` явно отмечает пробелы: endpoint identity, нетекстовая обработка и retention провайдеров не составляют полный descriptor согласия. Метаданные описывают текущую конфигурацию, не гарантируют будущий маршрут после изменения настроек.

Автоматическая стратегия, `PUT /api/v1/model-preferences`:

```json
{"quality":"high","provider":"auto"}
```

`provider` необязателен; отсутствие или `auto` означает общий пул подключённых облачных моделей. Разрешены `standard/high/maximum` и `auto/openai/gemini/zai/openrouter/kimi`. Для ограничения пула передайте `{"quality":"high","providers":["openai","zai","openrouter","lmstudio"]}`: непустой список без повторов, только при отсутствии закреплённого `provider`. Список ограничивает текст; сервисные поиск, vision, голос и профиль памяти сохраняют свои зависимости. Ключ и каталог определяют кандидатов, а реальная сетевая доступность выясняется при вызове.

Version-4 план содержит `routing[task]` — упорядоченный пул, `models[task]` — первый кандидат. После основных кандидатов сохраняется более лёгкая модель того же облачного провайдера, если профиль её предусматривает: это позволяет деградировать и аккаунту с одним API. Обычное качество не повышается до тяжёлой модели. `effectivePlan` дополнительно описывает `selection:"automatic-pool"` и всех `candidates`; фактический выбор и токены записываются в AI usage. Статические приоритеты не являются измеренным рейтингом качества или гарантией минимальной цены. На текстовых запросах учитываются активные вызовы и 30-секундный cooldown технического сбоя. Фото фиксирует первого совместимого vision-получателя на кадр. Переключение API приложения отключает общий пул в его scope.

Для автоматического сохранения не передаётся `mode:"automatic"`. Успех API возвращает полный нормализованный GET с `success:true`. API сохраняет общую стратегию и снимает старое перекрытие `API_AI_MODEL_PRESET` в одной транзакции, сохраняя прочие настройки. GET ничего не переводит в automatic и не переписывает Custom. Ошибка записи отменяет обе части; запоздалое чтение старой политики не заполняет кеш следующего хода.

Custom: `{mode:"custom", quality:"high", provider:"openai", routes:<все TEXT_TASKS>}`. Один провайдер (`openai/gemini/zai/openrouter/kimi/lmstudio`) применяется ко всем текстовым задачам. Каждый маршрут принимает строго `{model,maxTokens,reasoningEffort}`; отдельный provider внутри маршрута и прежний presetName не принимаются. Модель проверяется по подключённому каталогу выбранного провайдера, лимит 32–16384, рассуждения `none/low/medium/high`. Служебные подключения сервер определяет по провайдеру. Текстовые маршруты проверяются до записи; для новых Kimi/OpenRouter-профилей отсутствие отдельных сервисов отображается через serviceWarnings, для прежних профилей сохраняется полная проверка зависимостей. Локальные роли и произвольные ENV-ссылки не принимаются; сохраняется точный ID модели и её параметры.

План и базовый профиль записываются одной атомарной SQL-операцией. Новые auto-планы — version 4; закреплённые API/Custom — version 3. Старые version-1/2/3 планы не перекомпилируются при чтении; переход к пулу требует явного сохранения. Перед откатом на старый runtime сначала включите поддерживаемый им ручной профиль в текущей версии.

Входящие изображения имеют отдельный необязательный выбор через admin `GET/POST /api/image-recognition`: `{settings:null}` наследует текущую conversation-стратегию, `{settings:{provider:"lmstudio",model:"<catalog key>",maxTokens:4096,reasoningEffort:"none"}}` закрепляет локального получателя. Каталог проверяет `capabilities.vision === true` из [LM Studio List Models](https://lmstudio.ai/docs/developer/rest/list); загруженный instance ID нормализуется к ключу модели, имя модели не используется как доказательство поддержки vision. Допустимы лимиты 32–8192 и рассуждения none/low/medium/high. Credentials и endpoint задаются прежним подключением LM Studio. Настройка account-wide и имеет приоритет над текстовым app preset только для пикселей: Telegram/API фото, альбомы, health photo и AR localization используют один resolver. `capabilities.photo.vision` и AR capabilities описывают этого же получателя; смена модели или параметров отзывает подготовленный AR-план. Настройка читается на каждом фото без AI-вызова. Ошибка чтения/локальной модели/JSON не включает облачный fallback. Каталог подтверждается при сохранении; фактическая доступность проверяется inference. Новые tenant-ы и прежние установки без настройки сохраняют исходное поведение. Генерация картинок, browserVision и текстовая стратегия этой настройкой не меняются.

Новые базовые профили `kimi-full` и `openrouter-balanced` проверяют доступность текста независимо от отдельных сервисов. Одного ключа достаточно для сохранения авто/Custom и работы текстового канала; `serviceWarnings` и `effectivePlan.memoryEmbedding.available` показывают недоступные сервисы. Vision в этих профилях использует поддерживаемую модель того же API. Профиль векторов не переключается и не переиндексируется. Запуск без сохранённого/явного preset выбирает эти профили по единственному подключённому ключу; явный прежний выбор остаётся авторитетным.

Каталог OpenRouter ограничен поддерживаемыми Gemini Flash-Lite/Flash, Kimi K3.1 Pro, GLM 5.2 и GPT-5.4. Роли/качество задают приоритеты, текущая нагрузка и технические отказы — выбор резерва. Сетевого discovery на каждый ход нет, SDK-retry отключён, при успехе первой попытки этап требует одного AI-вызова. `provider.require_parameters:true` сохраняет требования JSON/инструментов; сортировка endpoint-ов использует price/latency/throughput. Это заданная стратегия, а не измеренная гарантия оптимальной цены или задержки. Числовой отказ модерации OpenRouter не запускает другую модель.

Прямой Kimi использует `https://api.moonshot.ai/v1`. K3 всегда рассуждает: общие none/low нормализуются в low, medium/high — в high; фиксированные sampling-параметры удаляются. Ключи Kimi Code/пользовательская подписка не заменяют Moonshot API key. [Официальные параметры Kimi](https://platform.kimi.ai/docs/api/models-overview), [маршрутизация OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection).
