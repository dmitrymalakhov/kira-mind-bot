# Локальный запуск

Нужен запущенный Docker Desktop с Docker Compose 2.24.4 или новее. Бот, PostgreSQL, Qdrant, админка и SSH-туннель работают в контейнерах. LM Studio использует нативное приложение на компьютере и его локальный API.

## Управление

Секреты и параметры конкретной установки хранятся только в `.env`, `.env.production` и `.kira-admin-state`. Безопасные шаблоны находятся в `.env.example` и `.env.production.example`; заполненные копии не добавляйте в Git. Данные владельца в `personality.json`, Telegram/browser-сессии, ключ SSH и резервные копии также остаются локальными в исключённых каталогах.

Из корня проекта:

```bash
./scripts/ops/local.sh up -d
./scripts/ops/local.sh ps
./scripts/ops/local.sh logs --tail=100 kira-mind-bot
./scripts/ops/local.sh stop
```

После изменений кода:

```bash
./scripts/ops/local.sh up -d --build
```

Админка открывается на localhost с портом `ADMIN_PORT` из `.env`. Логин и пароль задаются через `ADMIN_USERNAME` и `ADMIN_PASSWORD`; локальный установщик сохраняет их в `.env` и `.kira-admin-state`. Имена томов PostgreSQL и Qdrant задаются в `.env` через `POSTGRES_VOLUME_NAME` и `QDRANT_VOLUME_NAME`, файловое состояние хранится в `runtime-data/`. Перезапуск контейнера их сохраняет. Не удаляйте тома и не используйте `down -v`.

Для доступа к API с другого устройства настрой [Tailscale Serve](tailscale-api.md). Флаг `KIRA_API_PUBLISH=true` в `.env` сохраняет публикацию API при обычных запусках локального стека; Docker-порт остаётся на loopback, а приватный HTTPS предоставляет Tailscale.

Контейнеры запускаются снова при старте Docker Desktop, если не были явно остановлены. Компьютер должен оставаться включённым и не засыпать, чтобы получать сообщения и доставлять напоминания.

Перед коммитом запустите `npm run check:privacy`. Для автоматической проверки индекса включите репозиторные hooks: `git config --local core.hooksPath .githooks`. Нужен Node.js; при нестандартном пути задайте `KIRA_NODE_BIN` в окружении или локальный `git config kira.nodePath`. При обнаружении приватных данных проверка показывает только путь, строку и тип проблемы. Она не удаляет копии из старых коммитов: история проверяется и очищается отдельно.

## OpenAI через lmrouter

В `.env.production`:

```dotenv
OPENAI_API_KEY=your_openai_or_lmrouter_key
OPENAI_BASE_URL=http://lmrouter-tunnel:8080/v1
```

При BYOK используется ваш обычный OpenAI `sk-` ключ, если на gateway включён `ALLOW_OPENAI_KEY_PASSTHROUGH=true`. lmrouter также принимает собственные ключи `lmr_live_`.

В `.env`:

```dotenv
COMPOSE_PROFILES=lmrouter
LMROUTER_SSH_HOST=your_gateway_host
LMROUTER_SSH_USER=root
```

Туннель читает отдельный `runtime-data/lmrouter-ssh/id_ed25519` и pinned `known_hosts`. При переносе был создан отдельный ключ с доступом только к forwarding на `127.0.0.1:8080`; оболочка по этому ключу недоступна. Ключ не входит в Git или Docker-образ. API-порт туннеля доступен только внутри Docker-сети. Открывать gateway в интернет по HTTP не требуется.

В allowlist lmrouter нужны `/v1/models`, `/v1/chat/completions`, `/v1/responses`, `/v1/embeddings`, а для голосовых сообщений — `/v1/audio/transcriptions`. Для Decisions API дополнительно разрешается точный путь `/v1/decisions`; прежняя авторизация и остальные ограничения сохраняются. Доступность endpoint не переключает AI-политику Киры и не отменяет закреплённые маршруты моделей.

Можно задать HTTPS-адрес gateway напрямую в `OPENAI_BASE_URL`. Для прямого OpenAI укажите `https://api.openai.com/v1`; это требует доступности OpenAI из вашей сети. После изменения адресов, ключей или модели пересоздайте процессы:

```bash
./scripts/ops/local.sh up -d --force-recreate kira-mind-bot admin-panel
```

Кнопка обычного restart не перечитывает Docker `env_file`.

## LM Studio и гибрид

Запустите API LM Studio, загрузите нужную модель и задайте точный identifier из `/v1/models`. Например, через CLI LM Studio:

```bash
lms server start --port 1234 --bind 127.0.0.1
lms load your_model_key --identifier kira-local --context-length 32768 --yes
```

Окно контекста задаётся при загрузке модели в LM Studio и отличается от лимита ответа в настройках ролей бота. Окна 8192 токена может не хватать для личности, памяти и истории диалога: ошибка `exceed_context_size_error` означает, что модель нужно перезагрузить с большим окном. Начните с 32768, если модель и доступная память это позволяют. При автоматической загрузке после выгрузки или перезапуска LM Studio проверьте, что то же окно сохранено в настройках загрузки модели.

Точная модель по умолчанию задаётся в `.env.production`; выбор отдельных ролей в админке имеет приоритет:

```dotenv
LM_STUDIO_BASE_URL=http://host.docker.internal:1234/v1
LM_STUDIO_MODEL=your_local_model_identifier
LM_STUDIO_API_KEY=
```

Если LM Studio требует авторизацию, заполните его собственный API token. OpenAI-ключ для локального провайдера не используется. Параметры также можно редактировать в админке, в разделе API-ключей; затем пересоздайте контейнеры командой выше.

Выберите режим в разделе AI-моделей админки — сам пресет переключается сразу и сохраняется в PostgreSQL:

Вверху настроек находится блок «Модель общения Киры»: он показывает текущую модель обычного диалога и модель сложных ответов. Выберите профиль в списке «Модель и режим работы» и нажмите «Применить». Пока кнопка не нажата, карточки показывают только предпросмотр.

| Режим | Где выполняется работа |
|---|---|
| GPT-пресеты | OpenAI по `OPENAI_BASE_URL`, в перенесённом экземпляре через lmrouter |
| LM Studio · Локальный текст | Диалог, классификация, извлечение фактов и планирование локально; при отказе локальной модели текст не отправляется в облачный fallback |
| LM Studio + GPT · Гибрид | Повседневный текст и извлечение фактов локально, сложное рассуждение и браузерное планирование в GPT; при отказе LM Studio разрешён GPT fallback |

Во всех этих режимах веб-поиск, vision, распознавание аудио и существующая векторная память используют OpenAI через gateway. Локальный текстовый режим не означает полностью offline-бота. Memory embedding profile сохраняется прежним; для полностью локальной памяти нужна отдельная переиндексация всех коллекций с выбранной локальной embedding-моделью.

Качество structured output и tool calling зависит от локальной модели. Адаптер использует OpenAI-compatible Chat Completions и преобразует `json_object` в `json_schema`, поддерживаемый LM Studio. Подробнее: [API LM Studio](https://lmstudio.ai/docs/developer/openai-compat).

В том же блоке откройте «Локальные модели по задачам». Для каждой из трёх ролей выберите модель из каталога LM Studio, режим рассуждений и предел токенов, затем нажмите «Сохранить модели по задачам». Выбор применяется за 5 секунд без перезапуска. Профиль GPT игнорирует локальные роли; гибрид сохраняет облачные маршруты сложного ответа и браузера.

Пример настройки ролей для подходящей локальной модели: быстрый диалог — без рассуждений, до 768 токенов; быстрый анализ — без рассуждений, до 1536; глубокий анализ — с рассуждениями, до 4096. Одна модель для трёх ролей избегает загрузки нескольких тяжёлых моделей в память. При желании роли можно разнести; первый запрос к незагруженной модели включает задержку её загрузки. Uncensored/Obliterated-варианты отмечены в списке, но качество всё равно зависит от задачи.

Предел токенов включает скрытые рассуждения. Если ответ пустой из-за исчерпания лимита, увеличьте его или выключите рассуждения. Некоторые модели поддерживают только включение и выключение; уровни low/medium/high не гарантируют разницу в скорости. Точные приветствия проходят одним AI-вызовом, а обычный самодостаточный вопрос — классификацией и ответом; задачи с памятью или действиями могут требовать больше вызовов.

## Выборочный фон и экономия

Под моделью находится блок «Экономия и фоновые функции». При выключенной максимальной экономии работает только выбранный вами фон. Можно отдельно выключить рефлексию, изучение истории переписок, карточки наблюдений, консолидацию памяти, инициативные сообщения, развитие персонажа и регулярные AI-задачи.

Общий переключатель «Фоновое чтение Telegram» приостанавливает автоматическое чтение и обработку переписок, включая зависящие функции; их индивидуальные флаги сохраняются. Ручные запросы прочитать/проанализировать чат остаются доступны.

Максимальная экономия временно приостанавливает выбранные AI-функции, не стирая выбор. Можно настроить список заранее и затем снять общую паузу. Приостановленные функции помечены причиной в списке. Обычные напоминания работают всегда; DM Report и утренний дайджест управляются своими флагами и могут работать без AI даже при экономии. Применение занимает до 5 секунд и не требует перезапуска; уже начатый цикл может завершиться.

## Перенос данных и возврат на сервер

Копии серверного кода, конфигурации, файлового состояния, PostgreSQL и снимков всех Qdrant-коллекций сохранены в ignored `backups/`. Каталог содержит личные данные и секреты: храните его отдельно от публичных архивов и Git.

Перенос выполняется в таком порядке:

1. Создать предварительную копию и проверить восстановление на отдельном локальном instance.
2. Проверить gateway, модели и Telegram Bot API без запуска второго polling или второй пользовательской Telegram-сессии.
3. Остановить серверный бот и админку, выключить их Docker restart policy.
4. Снять окончательные дамп PostgreSQL, Qdrant snapshots, env и runtime-файлы; проверить SHA-256 после передачи.
5. Восстановить данные и сверить количество строк каждой таблицы и точное число точек каждой коллекции.
6. Запустить локальный бот, проверить пользовательское Telegram-соединение, Bot API и совместимость памяти.

Qdrant восстанавливается из collection snapshots с `priority=snapshot` на той же версии; это переносит векторы, payload и индексы. См. [официальную инструкцию восстановления](https://qdrant.tech/documentation/operations/snapshots/).

Серверные данные и контейнеры сохранены для возврата. Перед запуском серверного бота остановите локальный стек; две копии с одной Telegram-сессией одновременно запускать нельзя. Если после переключения бот уже работал локально, перед возвратом перенесите свежие локальные данные обратно — серверная копия остаётся на момент отключения. Команды и результаты конкретной миграции находятся в локальном каталоге `backups/`.
