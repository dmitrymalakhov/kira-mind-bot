# Внешнее API

API v1 позволяет подключить личное мобильное приложение к работающему боту. Диалог и команды проходят те же обработчики, оркестратор и агентов, что Telegram. Модель, личность, знания PostgreSQL/Qdrant, напоминания и регулярные задачи общие. Например, факт, сохранённый в Telegram, доступен в ответе мобильному приложению.

Для подключения другого устройства через приватный HTTPS см. [инструкцию Tailscale](tailscale-api.md).

История диалога и незавершённые уточнения разделены по каналам: мобильный чат продолжает свою сессию после перезапуска. Напоминания и фоновые результаты пока приходят в Telegram; push, streaming, загрузка фото и аудио не входят в v1. Доступ предоставляется одному владельцу инстанса. Это не многопользовательский сервис: токен даёт полномочия владельца, включая команды управления.

## Включение

В приватном `.env.production` укажи:

```dotenv
KIRA_API_ENABLED=true
KIRA_API_TOKEN=<случайный токен минимум из 32 символов>
KIRA_API_HOST=127.0.0.1
KIRA_API_PORT=3200
KIRA_ALLOWED_USER_ID=<Telegram ID владельца>
```

Сгенерировать токен можно командой `openssl rand -hex 32`. Клиент получает токен при личной настройке подключения и хранит его в iOS Keychain / Android Keystore. Общий секрет нельзя вшивать в распространяемый бинарник. Ротация: заменить токен в окружении и перезапустить runtime; прежние токен доступа и кнопки перестанут работать.

При запуске Node.js API слушает loopback. Для Docker добавь свободный порт `API_PORT` в compose `.env`, например `API_PORT=8320`, и используй overlay:

```bash
# VPS: обычный workflow сохраняет проверки project и storage.
SERVER_COMPOSE_OVERRIDE=docker-compose.api.yml make deploy
```

Для дальнейших Compose-операций с этим инстансом передавай тот же `SERVER_COMPOSE_OVERRIDE`, чтобы сохранить публикацию API. Overlay слушает `3200` внутри контейнера и публикует выбранный `API_PORT` только на `127.0.0.1`. Для каждого инстанса выбирай отдельный свободный порт; не меняй project или storage identity.

Для Docker Desktop можно сохранить `KIRA_API_PUBLISH=true` в `.env`: `scripts/ops/local.sh` сам добавит API overlay при следующих запусках.

Мобильному клиенту нужен HTTPS reverse proxy на этот loopback-порт либо приватный VPN. Internal health `3100` и admin API не публикуются вместе с внешним API. В reverse proxy сохрани `Authorization`, разреши JSON body до 64 KiB и установи время ожидания ответа, подходящее для длинных AI/браузерных задач, например `proxy_read_timeout 600s`. Доступ к API следует ограничить своим устройством или VPN. Сам runtime TLS не завершает.

## Контракт

Машиночитаемая спецификация: [openapi.json](../api/openapi.json). Все маршруты начинаются с `/api/v1`, требуют `Authorization: Bearer <token>` и возвращают `Cache-Control: no-store`. Клиент не передаёт `userId`, `chatId`, profile или произвольные callback data: идентичность берётся из серверной конфигурации.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/status` | Версия API, персонаж и канал уведомлений |
| GET | `/capabilities` | Поддерживаемые форматы и общий каталог возможностей бота |
| GET | `/history?limit=20` | Последние 1–20 реплик мобильной сессии в хронологическом порядке |
| GET | `/reminders` | Активные личные напоминания владельца из общего реестра |
| GET | `/tasks` | До 100 регулярных задач владельца; `hasMore` сообщает об ограничении |
| POST | `/messages` | Текстовый запрос или команда бота |
| POST | `/actions` | Нажатие кнопки из ответа API |
| GET | `/files/{id}` | Авторизованное скачивание созданного файла |

Знания доступны через обычные вопросы и существующие команды, например `Что ты помнишь обо мне?`, `/memory_search проект`, `Запомни, что…`. Управление напоминаниями и задачами — через текст, `/reminders`, `/tasks` и возвращённые кнопки. Это сохраняет существующие правила подтверждения и синхронизации памяти.

```bash
curl "$KIRA_API_URL/api/v1/messages" \
  -H "Authorization: Bearer $KIRA_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: mobile-message-0001' \
  --data '{"text":"Напомни завтра в 10:00 проверить макет приложения"}'
```

Тело `/messages`: только `{"text":"…"}`, до 8000 символов. Можно передать `/health`, `/reminders`, `/tasks` и другие команды владельца. HTTP-запрос ожидает окончания обработки; отключение клиента не отменяет уже начатое действие.

Ответ содержит массив `messages`, потому что команда может вернуть текст, файл и кнопки:

```json
{
  "messages": [
    {
      "id": -1792620000000001,
      "type": "text",
      "text": "Подтверди действие",
      "format": "plain",
      "buttons": [[{"text": "Подтвердить", "actionToken": "<непрозрачный токен>"}]]
    }
  ]
}
```

Типы сообщений: `text`, `notice`, `photo`, `document`, `voice`, `delete`. `format` — `plain` или `html`; HTML структурных карточек отображай безопасным ограниченным renderer. `replacesMessageId` означает обновление уже показанного сообщения; `delete` удаляет сообщение с указанным `id`. ID API отрицательные и не являются ID Telegram. При обновлении только клавиатуры поле `text` отсутствует: сохрани прежний текст. Кнопка содержит `actionToken` или обычный HTTP(S) `url`.

Нажатие: отправь `{"actionToken":"…"}` на `/actions` с новым `Idempotency-Key`. Кнопка действительна 15 минут и только до следующего запроса/нажатия в мобильном диалоге. Не разбирай токен и не конструируй его самостоятельно. Истёкшая кнопка возвращает `410 action_expired` — запроси актуальное меню снова.

У вложения `fileUrl` — относительный защищённый путь API или готовый HTTP(S) URL изображения. К относительному пути добавляй адрес своего сервера и заголовок авторизации; стороннему URL токен не передавай. Созданные файлы сохраняются в `runtime-data/api-files` и доступны 24 часа, включая после пересоздания контейнера. Просроченные файлы удаляются при последующих сохранениях.

## Повторы и ошибки

Для обоих POST обязателен `Idempotency-Key` из 8–128 букв ASCII, цифр, `_` или `-`; UUID подходит. Сохрани ключ вместе с исходным телом до отправки. При обрыве сети повтори **то же тело с тем же ключом**. Квитанция хранится в PostgreSQL и переживает рестарт. Повтор одного `actionToken` с другим ключом также не исполняет действие повторно. Клиент должен обновлять сообщения по `id`, чтобы повтор квитанции не дублировал карточки.

Одновременно выполняется один запрос, изменяющий мобильный диалог; чтение доступно параллельно. Лимит — 120 авторизованных HTTP-запросов в минуту на инстанс. Ошибки имеют вид:

```json
{"error":{"code":"conversation_busy","message":"Предыдущий запрос ещё выполняется."},"requestId":"…"}
```

| HTTP / code | Действие клиента |
| --- | --- |
| 400 `invalid_body` / `invalid_json` / `idempotency_key_required` | Исправить запрос |
| 401 `unauthorized` | Проверить токен |
| 409 `conversation_busy` | Подождать `Retry-After`, повторить с тем же ключом |
| 409 `idempotency_conflict` | Один ключ использован с другим телом; проверить очередь клиента |
| 409 `operation_uncertain` | Операция выполняется или результат не подтверждён после сбоя; проверить историю и реальные задачи, не переотправлять действие с новым ключом автоматически |
| 410 `action_expired` | Получить новое меню |
| 413 / 415 | Уменьшить тело / передать `application/json` |
| 422 | Формат или способ доставки недоступен через API |
| 429 `rate_limited` | Подождать `Retry-After` |
| 500 `internal_error` | Сохранить `requestId`; проверить состояние перед повтором |

Обычный ответ бота об ошибке бизнес-операции может приходить с HTTP 200 — так же, как текстовая ошибка в Telegram. Квитанции мутаций намеренно не удаляются автоматически, чтобы старый повтор не запустил действие заново. Не очищай `api_operations`, пока клиент может повторять соответствующие запросы. После неопределённого результата API не обещает автоматическое восстановление: уже выполненный внешний эффект нельзя безопасно откатить HTTP-повтором.
