# Kira Mind Bot

Персональный Telegram-ассистент с долговременной памятью, напоминаниями, доступом к интернету, браузерными действиями, анализом переписок и веб-панелью управления.

Основной сценарий проекта: бот поднимается прямо на своём VPS через Docker Compose. Данные живут в PostgreSQL и Qdrant на вашем сервере, а внешние API используются только для конкретных функций вроде OpenAI, Google Maps, Ideogram и Telegram User Client.

---

## Быстрый старт

Нужно: VPS с Ubuntu/Debian, `git` и доступом к Docker или `sudo/root` для его установки.

```bash
git clone <repo>
cd kira-mind-bot
make install-server
```

> **Важно про `make`**
>
> `make` запускается на хосте, не в Docker.
> Это только короткая обёртка над shell-скриптами.
> На Ubuntu/Debian его можно поставить так:
>
> ```bash
> sudo apt update && sudo apt install -y make
> ```
>
> Если `make` на VPS не установлен, используй напрямую:
>
> ```bash
> ./scripts/ops/server-install.sh
> ```

Что делает установщик:

1. проверяет и при необходимости ставит Docker на VPS;
2. спрашивает ключи и базовые настройки;
3. создаёт `.env.production`, `personality.json` и состояние админки;
4. собирает и поднимает PostgreSQL, Qdrant, бота и admin panel;
5. печатает URL, логин и пароль панели управления.

Есть два пути запуска:

1. На самой VPS: заходишь на сервер, запускаешь `make install-server`, дальше живёшь через `make deploy`, `make logs`, `make logs-follow`, `make logs-no-db`, `make pause`.
   Это основной и самый прямой путь, если у тебя есть shell-доступ к серверу.
2. С локальной машины на удалённый VPS: запускаешь `make remote-install SERVER_IP=<ip>` у себя локально, а установка и деплой идут по SSH.
   Этот путь нужен, если удобнее управлять сервером с ноутбука и не работать внутри shell на VPS.

Если `make` нет:

1. На самой VPS используй `./scripts/ops/server-install.sh`, `./scripts/ops/server-deploy.sh deploy`, `./scripts/ops/server-deploy.sh logs`, `./scripts/ops/server-deploy.sh logs -f`, `./scripts/ops/server-deploy.sh logs --no-postgres`, `./scripts/ops/server-deploy.sh logs --no-postgres --no-qdrant`.
2. С локальной машины используй `./scripts/ops/install.sh --server-ip <ip>` и `./scripts/ops/deploy.sh --kira-mind-bot --admin-panel --server-ip <ip>`.

Если проект уже поднят и нужно просто обновить код:

```bash
git pull origin main
make deploy
```

Если сборка сломалась из-за Docker cache или места на диске:

```bash
git pull origin main
make deploy-clean
```

## Частые команды

Команды короче и запоминаемее через `make`; shell-скрипты остаются внутренним backend-слоем.

Если `make` на хосте нет, используй эквивалентные команды напрямую из `scripts/ops/`.

| Команда | Назначение |
|---------|------------|
| `make install-server` | Путь 1: первый запуск прямо на VPS |
| `make remote-install SERVER_IP=<ip>` | Путь 2: установка на удалённый VPS с локальной машины |
| `make remote-deploy-all SERVER_IP=<ip>` | Путь 2: деплой бота и админки с локальной машины |
| `make deploy` | Обычный redeploy |
| `make deploy-clean` | Redeploy с безопасной очисткой Docker cache |
| `make status` | Статус сервисов |
| `make logs` | Последние логи всего стека |
| `make logs-follow` | Live-логи всего стека |
| `make logs-no-db` | Логи стека без `postgres` и `qdrant` |
| `make logs-no-db-follow` | Live-логи стека без `postgres` и `qdrant` |
| `make pause` | Остановить только `kira-mind-bot` и `admin-panel` |
| `make restart` | Перезапустить app-сервисы |
| `make stop` | Остановить весь стек |
| `make help` | Показать все доступные цели |

Какой путь использовать:

- первый запуск на VPS: `make install-server`
- обычное обновление: `make deploy`
- временно притушить приложение: `make pause`
- посмотреть последние логи: `make logs`
- посмотреть логи только приложений: `make logs-no-db`
- смотреть live-логи: `make logs-follow`

Два пути установки и деплоя:

1. Прямо на VPS через `scripts/ops/server-install.sh` и `scripts/ops/server-deploy.sh`.
   Подходит, если у тебя есть shell-доступ к серверу и ты хочешь выполнять все операционные команды на месте.
2. С локальной машины через `scripts/ops/install.sh` и `scripts/ops/deploy.sh`.
   Подходит, если удобнее деплоить по SSH с локального компьютера, не заходя в shell сервера для каждого шага.

`make` нужен только как shortcut на хосте. Docker-контейнерам он не нужен.
`make logs -f` не подойдёт, потому что `-f` обрабатывает сам `make`; для follow-режима используй `make logs-follow`.
Если нужен общий поток без шумных инфраструктурных логов, используй `make logs-no-db` или прямой вызов `./scripts/ops/server-deploy.sh logs --no-postgres --no-qdrant`.

## Что умеет бот

### Диалог и память

- ведёт диалог с учётом истории и долговременной памяти;
- запоминает факты по просьбе и автоматически извлекает важное из разговоров;
- хранит факты по доменам: `work`, `health`, `family`, `finance`, `education`, `hobbies`, `travel`, `social`, `home`, `personal`, `entertainment`, `contacts`, `general`;
- показывает сводку того, что знает о владельце;
- в проактивных подсказках старается объяснять, из какой переписки или контекста взята информация, и не подставлять догадки вместо неизвестного источника;
- умеет забывать факты, показывать историю изменений и отчёты о качестве памяти;
- фоново консолидирует знания, строит инсайты и запускает самоизучение.

Примеры:

```text
Запомни, что я работаю над Kira Mind Bot
Что ты помнишь обо мне?
Забудь, что я живу в старом районе
Покажи историю факта про работу
Изучи себя и свои потребности
```

#### Важно

Память теперь использует стабильный embedding-profile `stable-1536` (`openai:text-embedding-3-small`, `1536`, `Cosine`).

Если после обновления в логах появляется ошибка про несовместимость Qdrant-коллекции и `memory profile`, значит старая memory-коллекция была создана с другой размерностью. В этом случае нужно пересоздать такую коллекцию или вручную мигрировать её данные; простое переключение `AI_MODEL_PRESET` это не чинит.

### Напоминания и планирование

- создаёт напоминания естественным языком;
- поддерживает перенос, редактирование, отмену и повторяющиеся сценарии;
- умеет работать с напоминаниями в личном чате, группах и контексте контактов;
- присылает утренний дайджест;
- может создавать напоминания из договорённостей, найденных в переписке.

Примеры:

```text
Напомни завтра в 9:30 позвонить врачу
Каждый понедельник в 10 напоминай проверить отчёты
Перенеси напоминание про врача на пятницу
Измени напоминание про отчёт: текст: проверить финальные цифры
Отмени все напоминания на сегодня
```

### Telegram User Client

Если задать `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `TELEGRAM_SESSION_STRING`, бот получает доступ к вашему Telegram-аккаунту через пользовательскую сессию.

- показывает непрочитанные сообщения и делает сводку входящих;
- анализирует личные и групповые переписки;
- строит профиль контакта и сохраняет найденные факты в память;
- готовит черновики и отправляет сообщения после подтверждения;
- планирует отложенную отправку;
- может вести переговоры от вашего имени;
- фоново изучает личные переписки, если режим включён.

Примеры:

```text
Покажи непрочитанные сообщения
Изучи чат с женой за неделю и запомни важное обо мне
Напиши маме, что я задержусь на полчаса
Отправь в чат команды: завтра встречаемся в 11
Договорись с поставщиком о доставке цветов завтра
```

### Здоровье

Бот ведёт дневник наблюдений. Это не диагноз и не медицинская рекомендация.

- фиксирует еду, напитки, симптомы, кожу, давление, лекарства и заметки;
- принимает фото еды, кожи и показаний приборов;
- подсказывает, каких деталей не хватает для записи;
- замечает тревожные признаки без постановки диагноза;
- строит наблюдательные паттерны и напоминает проверить динамику;
- может ставить follow-up напоминания, чтобы проверить динамику;
- умеет экспортировать дневник за период.

Примеры:

```text
Запусти дневник здоровья
Запиши: съел креветки, через час зуд на руках 6 из 10
Запиши давление 120/80, пульс 72
Сохрани фото того, что я ем
Выгрузи дневник здоровья за 30 дней
```

### Интернет, браузер, карты и медиа

- ищет актуальную информацию через OpenAI web search;
- работает в браузере через Playwright: открыть сайт, нажать кнопку, заполнить форму, скачать файл;
- сохраняет браузерные сессии и может продолжить незавершённую задачу;
- для паролей, 2FA, captcha, платежей и юридически значимых действий требует явного участия владельца;
- умеет работать с Google Maps: адреса, маршруты и места рядом;
- распознаёт голосовые сообщения, анализирует изображения и делает OCR;
- генерирует изображения через Ideogram.

Примеры:

```text
Найди последние новости про OpenAI
Зайди на сайт клиники и запиши меня к врачу
Скачай PDF со страницы
Найди кафе рядом
Как добраться до Красной площади?
Что на этом фото?
Прочитай текст на изображении
Нарисуй кота в стиле акварели
```

### Групповые чаты

По умолчанию бот в группе реагирует только на прямое упоминание.

Есть два режима:

| Режим | Поведение |
|-------|-----------|
| Приватный | Посторонним отвечает без раскрытия личных данных владельца. |
| Публичный | Может отвечать всем участникам, но только в рамках разрешённых функций и доменов памяти. |

В публичном режиме доступны диалог, справка, поиск, карты и генерация изображений. Личные функции владельца недоступны другим участникам: чтение переписок, отправка сообщений, переговоры, личные напоминания и админ-команды.

Для каждого чата можно настроить:

- публичный режим;
- разрешённые домены памяти;
- запрещённые темы;
- распознавание владельца по имени и Telegram-никнейму;
- группы чатов для анализа и умного отслеживания важных сообщений.

## Установка на VPS

### 1. Подготовить сервер

Подойдёт Ubuntu 20.04+ или Debian 11+. Минимально: 1 CPU, 2 GB RAM, 20 GB диска.

На VPS должны быть:

- git checkout проекта;
- доступ к Docker или возможность поставить Docker через `root`/`sudo`;
- при необходимости уже настроенный VPN на уровне хоста.

Важно: если Telegram или другие внешние сервисы доступны только через VPN, VPN должен быть настроен на уровне самого VPS или сетевого маршрута Docker-хоста. Приложение proxy самостоятельно не настраивает.

### 2. Подготовить ключи

Обязательно:

| Что | Где взять |
|-----|-----------|
| OpenAI API key | [platform.openai.com/api-keys](https://platform.openai.com/api-keys) |
| Telegram bot token | [@BotFather](https://t.me/BotFather), команда `/newbot` |
| Telegram User ID владельца | [@userinfobot](https://t.me/userinfobot) |

Опционально:

| Что | Для чего |
|-----|----------|
| Google Maps API key | карты, адреса, маршруты, места рядом |
| Ideogram API key | генерация изображений |
| Telegram API ID + Hash | чтение переписок и отправка от имени пользователя |

### 3. Клонировать репозиторий

```bash
git clone <repo>
cd kira-mind-bot
```

### 4. Запустить установщик

```bash
make install-server
```

В конце будет напечатан блок вида:

```text
╔══════════════════════════════════════════╗
║        🌐 ПАНЕЛЬ УПРАВЛЕНИЯ              ║
╠══════════════════════════════════════════╣
║  URL:     http://YOUR_IP:8742            ║
║  Логин:   admin                          ║
║  Пароль:  xK7mP2nQ9rL4vY6w               ║
╚══════════════════════════════════════════╝
```

### 5. Настроить личность

В панели управления откройте раздел “Личность” и заполните:

1. имя владельца;
2. Telegram-никнейм владельца без `@`;
3. стиль общения и биографию, если нужно;
4. варианты настроения;
5. сохраните изменения и перезапустите бота.

Если на сервере не хотите случайно перетереть локальный `personality.json` при `git pull`, можно пометить его как локально изменённый:

```bash
git update-index --assume-unchanged personality.json
```

### 6. Получить Telegram Session String

Нужно только для функций Telegram User Client.

```bash
./scripts/get-telegram-session.sh
```

Скрипт авторизует пользовательскую Telegram-сессию через Docker и выведет `TELEGRAM_SESSION_STRING`. После этого вставьте его в панель управления или `.env.production`.

### 7. Включить публичный режим в группе

1. Добавьте бота в группу.
2. В BotFather отключите privacy mode, если бот должен видеть сообщения в группе.
3. В панели управления откройте “Чаты бота”.
4. Включите публичный режим для нужного чата.
5. Выберите домены памяти, которые можно использовать в этой группе.
6. Добавьте запрещённые темы, если нужно.

### 2. Установка с локальной машины на удалённый VPS

Этот путь нужен, если вы хотите запускать установку не на самом сервере, а со своей локальной машины по SSH.

Первый запуск:

```bash
make remote-install SERVER_IP=<ip>
```

Что требуется локально:

- `ssh` и `scp`;
- доступ по ключу к `root@<ip>` или готовность настроить его во время установки;
- локальные `bash`, `git` и доступ к репозиторию.

Обычный деплой после этого:

```bash
make remote-deploy-all SERVER_IP=<ip>
```

Если нужно деплоить только часть стека:

```bash
make remote-deploy-bot SERVER_IP=<ip>
make remote-deploy-admin SERVER_IP=<ip>
```

## Веб-панель

После деплоя панель доступна по адресу, который печатает установщик или redeploy-скрипт. На VPS это будет IP хоста, а при локальном запуске на macOS fallback-адресом будет `http://localhost:PORT`.

Порт, логин и пароль сохраняются в `~/.kira-admin-state`.

Что можно делать в панели:

- менять API-ключи и токены;
- переключать AI preset для runtime-маршрутизации задач между OpenAI, OpenRouter, Gemini и Z.ai;
- редактировать параметры PostgreSQL и Qdrant;
- задавать Telegram User Client session string;
- менять часовой пояс и срок хранения выполненных напоминаний;
- включать и выключать публичный режим групп;
- настраивать расписание проактивных сообщений и дайджестов;
- редактировать личность бота;
- управлять чатами, доменами памяти и запрещёнными темами;
- смотреть статус контейнеров;
- перезапускать сервисы после изменения настроек.

Важно: conversational `AI preset` и memory embeddings теперь разделены. Переключение preset меняет генеративный контур, но не меняет отдельный stable memory profile, через который бот пишет и читает память из Qdrant.

Через `.env.production` пока удобнее настраивать часть фоновых режимов: консолидацию памяти, фоновое изучение личных переписок и утренний дайджест.

### Несколько инстансов на одном VPS

Каждый инстанс должен находиться в отдельной папке и иметь отдельные `.env.production`, `personality.json`, Telegram bot token, PostgreSQL, Qdrant и админку. PostgreSQL и Qdrant наружу не публикуются: одинаковые внутренние адреса `postgres:5432` и `qdrant:6333` относятся к разным изолированным Docker-сетям.

Из-за разных сетей DNS-имя `postgres` во втором боте указывает только на PostgreSQL второго Compose project, а `qdrant` — только на его Qdrant. Физические данные лежат в volumes с именем инстанса, поэтому SQL-данные, память Qdrant и коллекции одного бота не доступны другому через штатную конфигурацию.

Для существующей установки в `/opt/docker/kira-mind-bot` ничего дополнительно задавать не нужно: имя папки даёт прежний project name `kira-mind-bot`, используются текущие volumes `kira-mind-bot_postgres_data` и `kira-mind-bot_qdrant_storage`, а текущие настройки админки переносятся из `.env` в локальный `.kira-admin-state`.

Для второго бота создайте соседнюю папку и выполните установку из неё:

```bash
cd /opt/docker
git clone https://github.com/okurilo/kira-mind-bot.git kira-wife
cd kira-wife
make install-server
```

Установщик предложит `kira-wife` как имя инстанса по имени папки и автоматически выберет свободный порт админки. Для полной явности значения можно задать в `.env.production`:

```env
# /opt/docker/kira-wife/.env.production
KIRA_INSTANCE_NAME=kira-wife
```

`ADMIN_PORT` хранится в локальном `.kira-admin-state`. Если порт не задан при первом запуске, выбирается свободный порт из диапазона `7000–8999`; после выбора он остаётся стабильным. Админки доступны по одному IP сервера, но на разных портах, например `http://server-ip:7875` и `http://server-ip:7876`.

Итоговая изоляция второго инстанса:

| Ресурс | Основной бот | Второй бот |
|---|---|---|
| Каталог | `/opt/docker/kira-mind-bot` | `/opt/docker/kira-wife` |
| Compose project / bot container | `kira-mind-bot` | `kira-wife` |
| PostgreSQL volume | `kira-mind-bot_postgres_data` | `kira-wife_postgres_data` |
| Qdrant volume | `kira-mind-bot_qdrant_storage` | `kira-wife_qdrant_storage` |
| Docker network | `kira-mind-bot_default` | `kira-wife_default` |
| Админка | `server-ip:7875` | отдельный свободный порт |

Не копируйте из основного каталога файлы `.env`, `.kira-admin-state`, `personality.json` и `.env.production` без последующей замены токенов и `KIRA_INSTANCE_NAME`. Если новое имя совпадает с project name, уже запущенным из другой папки, скрипт остановит запуск до обращения к Compose. Если у нового инстанса занят admin-порт и ещё нет собственного state-файла, будет выбран другой свободный порт.

При первом redeploy существующей установки скрипт переносит текущие `ADMIN_PORT`, `ADMIN_USERNAME` и `ADMIN_PASSWORD` из compose-файла `.env` в локальный `.kira-admin-state`. Это сохраняет адрес и credentials админки, одновременно изолируя их от других инстансов.

## Локальная разработка

Бот:

```bash
make install
make build
make dev
```

Админ-панель:

```bash
make install-admin
make dev-admin
```

Полезные цели:

```bash
make test
make lint
make build-all
```

Для локального запуска нужен `.env.development` с теми же обязательными переменными, что и production.

Удалённый путь с локальной машины тоже запускается не для разработки, а для деплоя: он использует `scripts/ops/install.sh` / `scripts/ops/deploy.sh`, SSH и `docker-compose.yml` для удалённого VPS.

## Архитектура

```text
Telegram Bot API / Telegram User Client
              |
              v
        grammy + session
              |
              v
        Orchestrator
   классификация интента -> план -> агенты
              |
              v
  conversation / reminder / health / browserTask
  readMessages / sendMessage / negotiateOnBehalf
  webSearch / maps / imageAgent / imageGeneration
              |
              v
  Services: PostgreSQL, Qdrant, OpenAI / OpenRouter /
            Gemini / Z.ai, Google Maps, Ideogram,
            Playwright, Telegram MTProto
              |
              v
  Schedulers: proactive, dmReport, memoryInsight,
              memoryConsolidation, personalChatMemory,
              reflection, morningDigest, chatGroupTracker
```

Ключевые части:

- `index.ts`: запуск бота, Telegram events, callbacks, медиа и планировщики;
- `orchestrator.ts`: классификация интентов и маршрутизация;
- `agents/*`: прикладные агенты для диалога, напоминаний, Telegram, браузера, карт, здоровья и изображений;
- `services/*`: интеграции, репозитории, память и фоновые сервисы;
- `admin-panel/*`: React/Vite UI и Node.js backend панели управления.

Инфраструктурно проект живёт в двух deployment-сценариях:

- `docker-compose.server.yml`, `scripts/ops/server-install.sh`, `scripts/ops/server-deploy.sh` — основной VPS-first поток;
- `docker-compose.yml`, `scripts/ops/install.sh`, `scripts/ops/deploy.sh` — путь для удалённого деплоя с локальной машины на VPS.

## Ограничения и важные замечания

| Тема | Что важно знать |
|------|-----------------|
| Доступ | Личный режим рассчитан на одного владельца через `KIRA_ALLOWED_USER_ID`. |
| Данные | PostgreSQL и Qdrant живут в Docker volumes на вашем сервере. |
| Telegram User Client | Без пользовательской сессии недоступны чтение переписок, контакты, отправка от имени пользователя и переговоры. |
| Google Maps | Без ключа Google Maps не работают карты и маршруты. |
| Ideogram | Без ключа Ideogram недоступна генерация изображений. |
| Здоровье | Дневник здоровья фиксирует наблюдения, но не ставит диагнозы. |
| Браузер | Пароли, 2FA, captcha, платежи и критичные действия требуют участия владельца. |
| Группы | Для полноценной работы в группах отключите privacy mode у бота в BotFather. |
| Публичный режим | Заполните Telegram-никнейм владельца в личности, чтобы бот корректно распознавал упоминания. |
| Qdrant | Рабочий и поддерживаемый вариант векторной памяти сейчас Qdrant. |
