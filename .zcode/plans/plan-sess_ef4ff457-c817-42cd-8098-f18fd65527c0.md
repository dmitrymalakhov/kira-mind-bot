## Правки

### 1. `scripts/testServerCommon.sh` — 3 изменения

**A. Добавить qdrant в `storage-bad` stub** (после строки 32):
Сейчас в режиме `storage-bad` функция `docker_ps` возвращает `postgres-id`, но не `qdrant-id`, поэтому bad-case для qdrant-хранилища фактически не проверяется (тест падает раньше на postgres). Добавить строку:
```
storage-bad:*service=qdrant*) echo "qdrant-id" ;;
```
И расширить stub `docker_inspect` для `qdrant-id` в режиме storage-bad — возвращать чужой volume `volume|foreign_qdrant_storage`.

**B. Тест-кейс ветки ошибки `ensure_admin_state`** (server-common.sh:308-312: порт занят + state-файл существует → `return 1`):
Создать `ADMIN_STATE_FILE` с `ADMIN_PORT=8123`, выставить stub так, что `admin_port_is_available_for_instance` возвращает отказ (через `FAKE_HOST_PORT_BUSY=true` или мок docker_ps с чужим контейнером на порту), вызвать `ensure_admin_state` и ожидать ненулевой exit. Сейчас покрыт только путь «нет state → fallback на find_available_admin_port».

**C. Тест-кейс sanitize fallback** (server-common.sh:23-25: дефолт `kira-mind-bot` при невалидном имени):
```
KIRA_INSTANCE_NAME="!!!"
[ "$(resolve_instance_name)" = "kira-mind-bot" ]
unset KIRA_INSTANCE_NAME
```
Сейчас есть только success-case `"Kira Second Bot"` → `kira-second-bot`.

### 2. `scripts/ops/deploy.sh` — убрать production IP из default

Строка 18: `SERVER_IP="165.232.120.123"` — реальный production-адрес в исходнике (footprint/инфо-утечка). Заменить на обязательный аргумент: если `--server-ip` не передан — показать `show_help` с сообщением, что IP обязателен. Makefile уже требует `SERVER_IP=...` явно во всех remote-* таргетах, так что текущие пользователи не сломаются.

`test(ops): покрыть ветки безопасности multi-instance` (основная масса — тесты) — или `fix(ops): ...` если трактовать IP как фикс. Уточню тип по факту: если убрать IP — это поведенческое изменение, тогда `fix(ops): убрать production IP и покрыть ветки безопасности деплоя`.
